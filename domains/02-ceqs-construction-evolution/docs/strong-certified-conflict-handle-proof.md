# CE-QS v1.1 — Strong Certified Conflict Handles
## Extended Trace Semantics, a Published Lattice Adapter, and Public Blame Proofs

**Status:** proof continuation from v1.0.  
**Date:** 2026-09-09.  
**Track:** hidden-signer Target \(B_1\).  
**Claim boundary:** v1.1 strengthens the trace semantics and gives a concrete **classical-ROM lattice adapter theorem sketch** based on published accountable-anonymity machinery. It does not claim a complete QROM proof or a measured <32-KiB implementation.

---

# 0. Why v1.0's TT1–TT5 need strengthening

The 2025 preprint *Traceability for Free: Traceable Ring Signatures Revisited* identifies a gap in the classic Fujisaki–Suzuki security notions.

The traditional trio:

- anonymity;
- linkability;
- exculpability,

does not by itself capture all attacks specific to tracing and does not imply unforgeability.

The paper introduces:

- **extended linkability**;
- **extended exculpability**,

and additionally shows that tracing can be \(O(1)\) when both input signatures are already valid.

CE-QS should not freeze a weaker trace interface than the state of the art.

Accordingly, v1.1 replaces the informal TT1–TT5 abstraction with a **Strong Certified Conflict Handle (SCCH)** interface.

---

# 1. SCCH syntax

An SCCH scheme is:

\[
\mathsf{SCCH}
=
(
Setup,
KeyGen,
Handle,
VerifyHandle,
SameSigner,
TraceConflict,
VerifyTrace
).
\]

## Setup

\[
pp\leftarrow Setup(1^\lambda).
\]

## Key generation

\[
(pk^T,sk^T)\leftarrow KeyGen(pp).
\]

The public trace key is registered in the epoch registry.

## Handle generation

For conflict topic \(\tau\) and message \(M\):

\[
h\leftarrow Handle(sk^T,\tau,M).
\]

## Handle verification

\[
VerifyHandle(pk^T,\tau,M,h)\in\{0,1\}.
\]

In CE-QS the final public observer normally does not know which \(pk^T\) generated \(h\).

The signer's local TagZK and the outer BatchZK certify this relation anonymously.

## Same-signer relation

For two valid same-topic handles:

\[
SameSigner(h_0,M_0,h_1,M_1)\in\{0,1\}.
\]

This is permitted to reveal only equality/link information.

## Conflict trace

For:

\[
M_0\neq M_1,
\]

\[
TraceConflict(h_0,M_0,h_1,M_1)
\rightarrow
pk^T\ \text{or}\ \bot.
\]

## Public trace verification

\[
VerifyTrace(
pk^T,
\tau,M_0,h_0,M_1,h_1
)
\in\{0,1\}.
\]

This is deterministic/public and requires no tracing authority.

# 2. Validity-gated tracing

The 2025 revised TRS framework obtains \(O(1)\) tracing **provided both signatures are valid**.

CE-QS has exactly the machinery needed to exploit this style safely.

A pair of public handles is eligible for tracing only after:

1. \(QC_0\) verifies;
2. \(QC_1\) verifies;
3. the handles are members of their respective authenticated public lists.

Outer BatchZK soundness then guarantees that every eligible handle had a valid local certification proof.

Thus the trace primitive does not need to assign semantics to arbitrary malformed byte strings.

We define:

\[
ValidPair(QC_0,j_0,QC_1,j_1)=1
\]

only after those checks.

# 3. Strong SCCH security games

## S1. Handle correctness

For honestly generated handles:

\[
VerifyHandle(pk,\tau,M,h)=1.
\]

---

## S2. Single-handle privacy / pseudorandomness

Before a conflict, a handle reveals no registered identity beyond permitted leakage.

For CE-QS it is sufficient that, after the outer proof is simulated, public handle distributions for two eligible honest identities are computationally indistinguishable.

Advantage:

\[
\epsilon_{\rm handle-pr}.
\]

---

## S3. Conflict trace completeness

For:

\[
h_b\leftarrow Handle(sk,\tau,M_b),
\qquad
M_0\neq M_1,
\]

\[
TraceConflict(h_0,M_0,h_1,M_1)=pk
\]

except with:

\[
\epsilon_{\rm trace-cor}.
\]

---

## S4. Cross-key trace soundness

For two valid registered trace keys:

\[
pk_a\neq pk_b,
\]

valid handles generated by those different keys must not trace to either registered identity except with:

\[
\epsilon_{\rm trace-sound}.
\]

---

## S5. Extended exculpability / non-frameability

The adversary may:

- register malicious trace keys;
- observe/provoke honest handles;
- obtain proofs/certificates for other messages;
- control all non-target validators.

It wins if it creates two **valid certified** handle instances that pass:

\[
VerifyTrace(pk^\star,\ldots)=1
\]

for an honest target \(pk^\star\), while the target did not generate both conflicting handles.

Advantage:

\[
\epsilon_{\rm ext-exculp}.
\]

This is the primary blame-security game.

---

## S6. Extended no-split / counting soundness

For a fixed:

\[
(\tau,M),
\]

an adversary controlling \(r\) registered trace keys must not create more than \(r\) mutually non-equivalent valid certified handles that can all be counted as distinct signer contributions.

This is the CE-QS threshold-counting analogue of extended linkability.

In the v1.0 outer proof this property is also enforced structurally by distinct hidden validator indices, so S6 is defense-in-depth rather than the only counting mechanism.

# 4. Public blame interface

E-cash literature separates:

- identifying a double spender;
- publicly verifying guilt.

CE-QS adopts the same discipline.

Define:

\[
ExtractConflict(QC_0,QC_1)
\rightarrow
\{\beta_i\}
\]

where blame object:

\[
\beta_i=
(
i,
j_0,
j_1
)
\]

identifies one handle position in each already-public QC.

The complete evidence is:

\[
(QC_0,QC_1,\beta_i).
\]

No external sidecar is referenced.

---

# 5. VerifyBlame

\[
VerifyBlame(QC_0,QC_1,\beta_i)=1
\]

iff:

1. both certificates verify;
2. they have the same conflict domain;
3. their messages satisfy the BFT conflict predicate;
4. \(j_0,j_1\) are valid indices in the public handle lists;
5. the selected handles are therefore validity-gated;
6.

\[
VerifyTrace(
pk_i^T,
\tau,
M_0,
E_0[j_0],
M_1,
E_1[j_1]
)=1.
\]

This makes blame evidence self-contained and third-party checkable.

# 6. Blame soundness theorem

### Theorem 6.1

Assume:

- BatchZK soundness;
- local handle-certification soundness;
- authentication-signature security;
- SCCH extended exculpability.

If:

\[
VerifyBlame(QC_0,QC_1,\beta_i)=1
\]

for an honest validator \(i\) that did not contribute to both conflicting certificates, then at least one named primitive property failed.

Thus:

\[
\boxed{
\begin{aligned}
Adv^{BlameFrame}
\le{}&
2\epsilon_{\rm BatchSound}
+
2q\epsilon_{\rm LocalSound}\\
&+
2q\epsilon_{\rm SigForge}
+
\epsilon_{\rm ext-exculp}.
\end{aligned}
}
\]

### Proof

Certificate soundness supplies valid hidden vote/handle contributors for each public list.

The selected public handles are therefore valid certified instances.

If the honest target did not generate both yet `VerifyTrace` identifies it, this wins the extended-exculpability game, unless one of the certificate/local-certification assumptions failed first.

\[
\blacksquare
\]

# 7. Conflict completeness theorem under SCCH

For two accepted BFT certificates:

\[
|S_0|,|S_1|\ge q.
\]

Therefore:

\[
|S_0\cap S_1|
\ge
2q-n
=
f+1.
\]

For every:

\[
i\in S_0\cap S_1,
\]

same-hidden-set binding gives one certified public handle in each QC.

S3 then traces the pair to \(pk_i^T\).

Hence:

\[
\boxed{
|ExtractConflict(QC_0,QC_1)|
\ge
f+1
}
\]

except with certificate/trace correctness failure.

# 8. Direct-TRS baseline theorem

Before optimizing, there is a conceptually simpler hidden-signer QC.

Assume a traceable ring-signature scheme satisfying the **strengthened** security semantics above.

Every validator produces one TRS signature:

\[
\rho_i
\leftarrow
TRS.Sign(
sk_i,
R_e,
\tau,
M
).
\]

A quorum certificate is simply:

\[
\boxed{
QC_{\rm TRS}
=
(\rho_1,\ldots,\rho_s),
\qquad
s\ge q.
}
\]

Verification:

1. verify every ring signature;
2. reject any pair that is attributable/linkable to one signer for purposes of same-certificate duplicate counting;
3. require at least \(q\) distinct contributions.

Conflict extraction pairwise traces:

\[
QC_0\times QC_1.
\]

# 9. Direct-TRS security theorem

### Theorem 9.1

If the base TRS has:

- validity;
- anonymity;
- extended no-split/linkability;
- conflict trace completeness;
- extended exculpability;

then \(QC_{\rm TRS}\) is a sidecar-free hidden-signer accountable quorum certificate.

### Proof

Extended counting/linkability implies an accepted QC represents at least \(q\) distinct ring identities.

Two QCs therefore have at least:

\[
2q-n=f+1
\]

common signers.

Trace completeness reveals every common signer on conflict.

Extended exculpability prevents false blame.

\[
\blacksquare
\]

This theorem is useful because it proves that **threshold-ring aggregation is not logically necessary for Target \(B_1\)**.

Plain strong TRS is enough for theoretical functionality.

The difficulty is compactness.

# 10. Published PQ-TRS baseline and the semantic caveat

Feng–Liu–Wu–Li (CT-RSA 2020) and the expanded DCC 2021 work construct post-quantum traceable ring signatures using:

- NIZK proof of knowledge;
- collision-resistant hash;
- PRF with additional properties;
- lattice and symmetric-key instantiations.

The lattice construction is proved in QROM and has logarithmic signature size in the ring cardinality.

However, its security predates the 2025 extended-linkability/extended-exculpability correction.

Therefore:

\[
\boxed{
\text{the 2021 PQ TRS is evidence of QROM PQ traceability, but not automatically evidence for the 2025 strengthened semantics.}
}
\]

A strengthening/adaptation theorem is required before using it as the load-bearing SCCH instance.

\widehat t

# 14. Published public tracing algebra

For two valid authentication records with:

\[
t_0=t_1,
\qquad
c_0\neq c_1,
\]

the 2017 public tracing algorithm computes:

\[
\boxed{
y
=
(c_0-c_1)^{-1}
(
\widehat t_0-\widehat t_1
).
}
\]

That is an identity public key.

Their exculpability proof explicitly defines a false-accusation "bad pair" using the same equation and reduces such an accusation through:

- ZK simulation/extraction;
- accumulator/registration soundness;
- strong uniqueness of the wPRF.

This is a published proof pattern for the CE-QS blame equation.

# 15. LWR-SCCH adapter

Define a CE-QS topic adapter as follows.

Registry trace public key:

\[
y_i=F_{s_i}(A).
\]

Derive topic bases from a random oracle or canonical random-matrix expander:

\[
B_\tau=H_B(\tau,0),
\]

\[
\widehat B_\tau=H_B(\tau,1).
\]

Message challenge:

\[
c_M=H_c(\tau,M)\in\mathbb Z_p.
\]

Handle:

\[
\boxed{
h_i=
(t_i,\widehat t_i,\pi_i)
}
\]

with:

\[
t_i=F_{s_i}(B_\tau),
\]

\[
u_i=F_{s_i}(\widehat B_\tau),
\]

\[
\widehat t_i=u_i+c_M y_i.
\]

Local proof \(\pi_i\) establishes:

- registered \(y_i\);
- the three wPRF evaluations;
- the linear relation above.

# 16. LWR-SCCH correctness and trace theorem

For the same trace secret \(s_i\) and topic:

\[
t_{i,0}=t_{i,1}.
\]

For conflicting messages with:

\[
c_0\neq c_1,
\]

\[
\widehat t_{i,0}
-
\widehat t_{i,1}
=
(c_0-c_1)y_i.
\]

Therefore:

\[
\boxed{
y_i
=
(c_0-c_1)^{-1}
(
\widehat t_{i,0}
-
\widehat t_{i,1}
).
}
\]

This part is exact algebra.

# 17. LWR-SCCH counting soundness

For one fixed topic and message, the same secret key produces the same:

\[
t_i.
\]

The 2017 wPRF additionally has uniqueness/strong-uniqueness properties designed to make different secret keys collide on tag outputs only negligibly.

Therefore duplicate-counting can use:

\[
t_i
\]

as a public same-signer handle.

In v1.0 this is not the sole mechanism, because the BatchZK relation also proves hidden validator indices distinct.

The two mechanisms reinforce one another.

\[
y\neq F_s(x)

# 19. Security status of the LWR-SCCH adapter

The 2017 Theorem 5.2 proves its k-times anonymous-authentication protocol secure assuming:

- secure strongly unique wPRF with efficient protocols;
- secure accumulator;
- secure credential/signature scheme;
- secure ZKAoK;
- SIS;
- random oracle.

Its definitions include:

- anonymity;
- detectability;
- exculpability for users;
- exculpability for the group manager.

For CE-QS, we remove the group-manager architecture and replace it with the fixed validator registry.

The remaining adaptation is:

1. derive topic bases from \(\tau\);
2. derive challenge \(c\) from \(H_c(\tau,M)\);
3. bind the proof to the CE-QS registered trace key.

Because distinct message inputs to a classical random oracle receive independent random challenges, the proof strategy is closely aligned with the published random-challenge authentication game.

However:

\[
\boxed{
\text{this exact CE-QS adapter has not yet been reduced formally to Theorem 5.2.}
}
\]

So the correct label is:

> **concrete published construction pattern + classical-ROM adapter proof obligation.**

# 20. QROM status of the LWR-SCCH adapter

The 2017 protocol predates the QROM-secure TRS work and states classical PPT/random-oracle security.

Therefore it does not close v1.0's quantum trace-tag problem.

There are two routes.

## Route A — prove the LWR-SCCH Fiat–Shamir/topic-hash adaptation in QROM

This includes the affine/challenge relation already isolated in v1.0.

## Route B — transplant the strengthened semantics into the 2021 QROM-secure PQ TRS framework

This avoids re-proving every Stern/Fiat–Shamir detail from scratch but requires showing the 2021 framework satisfies the 2025 extended notions.

Neither route is complete today.

# 21. Witness-authenticating NIZKs as a stronger optional local-proof layer

Witness-authenticating NIZKs introduce an identification interface for proofs and explicitly require:

- valid proofs cannot evade all valid witnesses;
- adversaries cannot use one witness to frame another;
- identifier uniqueness can prevent one proof from authenticating to two different strings.

These ideas align strongly with local certified conflict handles.

For the current v1.0 architecture, ordinary local sound ZK plus the SCCH exculpability game is sufficient.

waNIZK is therefore an optional strengthening rather than a required dependency.

# 22. Batch hiding remains the outer compression school

The outer BatchZK relation verifies \(q\) independent vote/handle contributions.

The STOC 2024 batch-proof result establishes:

- noninteractive BARGs for NP plus one-way functions imply noninteractive computational ZK arguments for NP;
- stronger somewhere-sound/extractable batch arguments yield stronger noninteractive hiding consequences.

This supports the v1.0 architectural decision:

\[
\boxed{
\text{first prove the batch relation soundly, then compile/bind privacy around the batch proof.}
}
\]

No concrete proof-size claim follows from this theorem alone.

# 25. Main theorem after v1.1

### Theorem 25.1 — Strong CE-QS composition

Let the v1.0 distributed-certified-handle protocol use an SCCH satisfying S1–S6.

Assume:

- QEUF vote signatures;
- local handle-certification soundness and ZK;
- outer BatchZK soundness and ZK;
- durable honest no-double-vote state.

Then:

1. every accepted certificate represents at least \(q\) distinct hidden registered voters;
2. a single certificate hides those identities from public observers;
3. two conflicting certificates expose at least:

\[
2q-n=f+1
\]

common identities;
4. every accusation has publicly checkable `VerifyBlame`;
5. an honest validator that did not sign both conflicts is not framed except with the sum of the primitive failure advantages.

The theorem is independent of whether SCCH is instantiated by:

- a TRS-derived handle;
- an LWR two-challenge handle;
- a future ML-DSA trace handle.

\[
\blacksquare
\]

# 27. Bottom line

v1.1 removes another home-grown part of the design.

The **two-challenge trace algebra and its anti-framing proof pattern already exist in lattice accountable-anonymity research**.

The remaining novelty is not the existence of conflict extraction itself.

It is integrating the strongest modern trace definitions with PQ security and batch compression tightly enough that a 43-of-64 BFT certificate remains practically compact.
