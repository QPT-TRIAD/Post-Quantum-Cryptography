# Milestone 3–4 — the normal form, the q-ary lattice, and the planted vector

**Gate passed.** `assert_in_lattice` holds for the planted vector at every size and embedding
factor tested, and every check that is claimed to catch a fault is *shown* to catch one.

## Why this milestone is the risky one

Design section 3.3 names it: **a wrong lattice reduces perfectly.** A transposed base, a stale `qI`
block, a sign error or an off-by-one all yield a full-rank lattice of the right determinant, which
BKZ reduces happily and reports a root-Hermite factor for that looks like every other root-Hermite
factor. There is no downstream signal.

So `assert_in_lattice` ran before any reduction code exists. It is one exact rational solve, it
takes seconds, and it works at any dimension — the cheapest falsifier available, and it decided the
construction before anything was built on it.

## Three wrong answers that each looked right

Every one of these produced a self-consistent object. Only the consistency check caught them.

**1. The relation carries a minus sign.** The instance defines `e = u - b`, so `b = A s - e (mod q)`
and *not* `+e`. Derived for a plus sign, the transformation still produces a normal form that
satisfies its own algebra — it simply describes a different instance. Caught by `check()`
immediately; nothing downstream would have looked unusual.

**2. `A' = +A₂A₁⁻¹`, not negative.** Substituting `s = A₁⁻¹(b₁ + e₁)` into `b₂ = A₂s - e₂` gives
`+A₂A₁⁻¹e₁ - e₂`. I dropped the sign in the substitution and wrote `A' = -A₂A₁⁻¹`. Also caught by
`check()`. Two sign errors in the same derivation, each invisible without the check.

**3. The sample's `% p` reduction is a single wrap at the top only when `p` divides `q`.** This is
the substantive one. The relation computes `b = (q//p) · (round(u·p/q) mod p)`. When `p | q`,
`(q//p)·p = q` exactly, so only the top bucket wraps and the residual is bounded by `q/(2p)` —
the recorded parameters, `2⁸ | 2¹⁶`, give the clean `[-128, 127]`.

When `p ∤ q` the multiplication exceeds `p` for many buckets and the reduction wraps repeatedly.
Measured at `q = 61, p = 19`: the residual reaches **23 out of 61** — a 38% noise rate — against
0.2% for the production pair. An instance at a non-divisor modulus is therefore a *different and
far noisier* object, not a scaled version of the production one.

The fix was to define the error as the signed representative of `u - b (mod q)`, which makes
`A s - e ≡ b` hold **by construction for any modulus**. The old expression agreed with it exactly
when `p | q`, which is why the default path looked correct.

## A consequence for the project's premise

Finding 3 matters beyond this module. The clean LWR regime requires `p | q`, and the recorded
production parameters satisfy it. But the sibling Grover project's worked instance uses
`q = 61, p = 19` — a non-divisor pair — so **the two projects' instances are not the same kind of
object**, and a result carried between them would not mean the same thing. Worth stating before
anything is compared.

## What the construction is

    Lambda = { (A c + q z, c) : c in Z^n, z in Z^m }   subset of   Z^m x Z^n

generated by `n` rows `(Aᵀ, I_n)` plus `m` rows `(qI_m, 0)`, determinant `q^m`. Kannan's embedding
adds the target row `(b, 0, M)`, giving determinant `q^m · M` and containing

    (b, 0, M) - (b - e, x, 0) = (e, -x, M)

which is short exactly because the normal form made `e` and `x` small. That vector — not a norm
threshold, not a nearby vector — is what the attack has to return.

The design document sketches it as `(-e, x, -M)`; that is the same vector times `-1`, and a lattice
is closed under negation, so the test compares up to sign rather than pinning a convention that
carries no information.

## The checks, and why both

| check | what it verifies | the bug it catches alone |
|---|---|---|
| structural | every row `(u, w)` satisfies `u ≡ A w (mod q)` | a row that is not in the lattice at all |
| volumetric | `\|det B\| == q^m` exactly | a basis satisfying the relation row-wise that spans a sublattice or superlattice |

They fail for different bugs, so both are required. Each is shown non-vacuous: a single-coordinate
perturbation trips the structural check, and doubling a `q` row — still congruent to zero, so still
structurally valid — trips only the volumetric one. That second case is the reason the pair exists
rather than one check.

`assert_same_lattice` is **imported from `engines/base_engine.py`, not redefined.** Two definitions
of "the same lattice" would be exactly the boundary drift this project's cross-check battery is
built to prevent.

## Supporting facts established along the way

- **`inverse_mod` needs the Chinese remainder theorem for a composite modulus.** Gauss-Jordan over
  `Z/105` can require *combining* rows to reach an invertible pivot rather than swapping one in:
  `[[3,1],[5,2]]` has determinant 1 and is invertible, while neither entry of its first column is
  invertible alone. A single-entry pivot search fails on a perfectly invertible matrix.
- **The pivot search is greedy, and greedy is exact only for one prime.** `q = 2^16` is one prime,
  so one pass suffices; several primes make the requirement an intersection of matroids where
  greedy is not guaranteed. Restarts cover the composite case, and the determinant check is what
  actually decides regardless of how the pivot was found.
- **`noise_bound` was wrong for non-divisor moduli** and is now *computed* over the `p + 1` rounding
  buckets rather than assumed to be `q/(2p)`. A bound that is too small rejects honest instances
  while looking like a lattice bug.
