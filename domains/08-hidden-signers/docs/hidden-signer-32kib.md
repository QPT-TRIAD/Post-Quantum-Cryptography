## 0. Answer

The v1.45 literature pass found no published scheme with a hidden 43-of-64 quorum, public keyless tracing, category-5 post-quantum security and 32 KiB. Treating this as frontier work — borrowing partial ideas across papers, gluing them, and testing each decision — this revision produces **Mode B**, the first design whose estimated certificate is under 32 KiB:

| Prover setting (VOLE-in-the-head, FAEST v2 formula) | Certificate | Fits 32,768 B |
|---|---:|---|
| 2^24-leaf trees, 16 grinding bits, 2^16-step challenge chain | **29,914 B** | yes |
| 2^32-leaf trees, 16 grinding bits, 2^16 chain | **26,624 B** (27,008 B under the stricter 2^18-gates-per-hash rule) | yes |
| 2^32-leaf trees, 32 grinding bits | 22,822 B | yes |
| 2^16-leaf trees, no grinding | 54,480 B | no |

**Security, best-known-attack estimates (log₂, quantum, query units):** framing/preimage **122.3** — the generic Grover bound for a 256-bit secret with 43×64 targets; the algebraic attacks (XL/hybrid) cost 240 and never beat it — evasion by key collision **150**, generic collision 271. In the v1.43 **attack-cost** D2 ledger (2^18 gates per evaluation) the framing row is 2^−149.6 per gate at 2^128 gates, a **19.6-bit margin**, the same accounting under which B0 passes. The **rigorous** D2 ledger also passes at n = 256 (v1.47): because the evidence is recovered publicly, the framing reduction is tight and needs no proof extraction; with expansion 512 and a 2^32-leaf prover the total is 2^−145 per gate (**15-bit margin**) at **30,810 B**. The proof-soundness row is modelled with DFMS22 and omits the multi-round loss; it is the backend's obligation. For comparison, the v1.45 Mode A handle scores **123.3 algebraically**, i.e. below generic; that finding came out of this round's tests and is why the handle is r⁷.

**What Mode B is:** a tested design with a size estimate and an attack-based security ledger. **What it is not:** a proven scheme. It has no zero-knowledge backend, no security theorem, no collaborative prover, and no dedicated cryptanalysis beyond the attack families tested here. The estimates use the standard XL/hybrid model under the semi-regularity heuristic. Section 5 lists what would make it real.

## 1. The glued ideas

| Source | Partial idea borrowed | Tested here |
|---|---|---|
| v1.24 contract; Fujisaki–Suzuki traceable ring signatures | An algebraic handle that reveals a signer only when it signs twice in one domain | Pair-search extraction (11 tests, all overlaps 22–43 at toy scale; full-size demo) |
| MQOM2 / KuMQuat ("One Tree", ePrint 2024/490) | A quadratic map needs **no intermediate witness** in a VOLE-in-the-head proof | Witness = 2n + 64 bits per seat |
| Ding–Yang cubic hash (broken by Aumasson–Meier); own test | Quadratic maps are **not collision-resistant**: F(x⊕δ)⊕F(x) is linear in x for fixed δ… **unless the map expands** | Linear-trick attack implemented: ~40% of δ's collide at m = N; 0 of 4,096 at m = N+16; model 2^(N−m) confirmed |
| Power S-boxes (Gold, inverse), MiMC x³, Rain | A **low-degree power permutation** of the secret r blocks its linear elimination | SAT experiments and XL/hybrid estimates: r⁷ handle = no handle (251); linear handle 123 |
| FAEST-d7 / QuickSilver | Degree-3 constraints on committed inputs at ~no extra witness | Size formula reproduces FAEST-256s/f and EM-256s/f exactly |
| v0.5 distinctness lemma | Distinct handles + binding ⇒ distinct seats; no selector-count constraints | Relation test (duplicate seat rejected) |
| v1.44 Theorem C | Attack-derived minimum τ, challenge bits and credential size | Same conventions, both 2^24 and 2^18 gates/hash |

## 2. Mode B

**Parameters.** n = 256; field GF(2^256) with x^256 + x^10 + x^5 + x^2 + 1; key map F: F₂^512 → F₂^812, a random quadratic map expanded from a 32-byte seed (12.7 MB, regenerated by every verifier); G(r) = r^7, a permutation because 7 ∤ 2^256 − 1 (x³ would **not** be one: 3 | 2^256 − 1).

**Registry.** Per epoch and conflict domain d, seat i draws a one-time opening (s, r) ∈ F₂^256 × F₂^256 and registers Y[d][i] = F(s‖r), 102 bytes. cfg commits to the epoch, the key-map seed and every Y. Registry cost: 102 B per seat per domain (6.5 KB per seat for 64 domains, 6.7 MB per seat for 2^16).

**Handle.** c = SHAKE256("CQ46/c" ‖ cfg ‖ d ‖ m) as a nonzero field element;

  Z = r^7 ⊕ c·s   (32 bytes).

**Certificate.** header 208 B ‖ 43 handles strictly increasing (1,376 B) ‖ proof ≤ **31,184 B**.

**Relation R_B.** Rows (i_j, s_j, r_j) aligned with the handles, with F(s_j‖r_j) = Y[d][i_j] and Z_j = r_j^7 ⊕ c·s_j. Committed witness per seat: s, r, one-hot selector = **576 bits**; constraints: 812 quadratic (key map, selected key is linear in the one-hot bits), 256 cubic (r^7 = r·r²·r⁴, the Frobenius factors are linear), 65 one-hot. Distinct seats follow from the strict ordering plus binding of F.

**Extraction.** For two accepted certificates with equal (cfg, d) and m₀ ≠ m₁: for each of the 43×43 handle pairs, s = (Z₀⊕Z₁)/(c₀⊕c₁), r = (Z₀ ⊕ c₀·s)^{1/7}, and look F(s‖r) up among the domain's 64 keys. A hit names the seat; (s, r) with both handles is public evidence (`verify_blame`). A double-signer always hits. A false pair gives a random 812-bit value, so a spurious hit has probability 64·2^−812.

**Full-size run** (`--demo-256`, pure Python + numpy): key map and 64 registry keys in 22.6 s; two conflicting frames of 1,584 B before the proof; extraction over all 1,849 candidate openings in 72.5 s recovered exactly the 22 common seats, and every blame re-verified. The extraction is 1,849 evaluations of F, about 3·10⁹ word operations: a few seconds single-threaded in C.

**Why each piece is there.**
- *Why one-time per-domain openings:* with a fixed (s, r), two handles in different domains give (c_d ⊕ c_d′)·s and reveal s. Tested (`test_cross_domain_handles_do_not_leak`).
- *Why r^7 and not r:* with Z = r ⊕ c·s the attacker substitutes r and attacks F with 256 unknowns instead of 512.
- *Why expansion 300:* a corrupt seat may otherwise register a key with two openings it knows, via one Gaussian elimination per δ.
- *Why no link tag:* the pair search replaces it; the registry lookup filters wrong pairs.

## 3. Attacks: tested at toy scale, estimated at n = 256

### 3.0 A0 — generic framing bound

Guess r with Grover, derive s = (Z ⊕ r⁷)/c linearly, check F: 2^(n/2) = 2^128 iterations, **2^122.3** with the 43×64 registry targets. No structured attack below beats this, so **122.3 bits (query units) is Mode B's framing security at n = 256**, exactly the generic level of a 256-bit secret. Verified consequence: the semi-regular estimator in §3.1 cannot see this attack (its cubic equations become linear once r is fixed), so §3.1's numbers are the cost of the *algebraic* route only.

### 3.1 A1 — algebraic framing (does the handle give algebraic leverage?)

Boolean system: 812 quadratic + 256 cubic equations in 512 unknowns. Semi-regular degree of regularity, XL at ω = 2, quantum hybridization (Grover over k guessed variables):

| Handle | Classical | Quantum | Note |
|---|---:|---:|---|
| none (F alone) | 385.8 | 251.3 | baseline |
| **r^7 (Mode B)** | 378.2 | **251.3** | equals baseline: the handle leaks nothing the model can use |
| r^3 | 337.8 | 244.8 | quadratic permutation, slightly weaker |
| **linear (Mode A)** | 148.8 | **123.3** | r eliminated: 256 unknowns, 812 equations |

Sweep over n (`sweep.py`): algebraic cost with the power handle ≈ n + 3 bits quantum, with the linear handle ≈ 0.45·n + 9. So the linear handle's algebraic route (123.3 at n = 256) drops **below** the generic bound of 128, while the r⁷ handle keeps the algebraic route at 251 (240 multi-target), far above generic. **Correction (v1.49 independent analysis):** the SAT experiments do *not* support the ranking. Measured slopes are 2.42 bits/n with no handle, 1.29 with the linear handle and 0.90–0.93 with r⁷: any handle lets the solver guess r and derive s (the generic attack), and r⁷ instances are *not* like bare key maps at toy scale. The r⁷-over-linear ranking rests on the XL/hybrid model only. The security bound is the generic 2^128 either way (v1.49 §9 items 3–5).

### 3.2 A2 — evasion (register a key with two openings)

For fixed δ, F(x⊕δ)⊕F(x) = A_δ x ⊕ b_δ is linear in x, consistent with probability ≈ 2^(N−m). Grover over δ: **2^((m−N)/2) = 2^150**. Empirical: N = 64, m = 64: 1,631/4,096 δ's collide (each by one linear solve); m = 72: 6/4,096 (model 16); m = 80: 0/4,096 (model 0.06); m = 96: 0. Generic BHT collision on 812 bits: 2^271. Raising the expansion to 400 costs 12 B per registry key and lifts the linear trick to 2^200; nothing in the certificate changes.

Also covered: with a **square** map (m = N), the same test finds collisions for 40% of δ's, which is why MQOM-style maps cannot be used as commitments without expansion (v1.44 §3.3 had flagged this). The collision code was checked against brute force at N = 10 and 12: for every δ it reports a collision exactly when one exists.

### 3.3 A3 — generic

Challenge c is public and message-derived; Grover on the 256-bit s given (Y, Z) is dominated by A1's hybrid. Registry keys are public data, not secrets.

### 3.4 Ledger (query units; v1.43 gate accounting adds ≥ 18 bits)

| Event | Quantum log₂ |
|---|---:|
| **Framing / honest-key preimage, generic Grover, multi-target** | **122.3** |
| Framing, best algebraic route (XL/hybrid), multi-target | 240 |
| Evasion by collision (linear trick, expansion 300) | 150 |
| Evasion by generic collision | 271 |
| Mode A linear handle, algebraic, for comparison | 123.3 |

**Against the v1.43 definitions.** Attack-cost D2 ledger (HRS16 search row, 2,752 targets, 2^18 gates per evaluation): framing gives log₂(Pr/G) = −149.6 at 2^128 gates, margin **19.6 bits** — the accounting under which B0 passes.

**Rigorous D2 ledger (v1.47, `modeB_rigorous_ledger_v1.47.py`).** A first pass assumed the framing reduction must extract the proof witness (Lemma L5), which would force n = 512 and 38–50 KB certificates. That is wrong for Mode B: the double-signing evidence (s, r) is recovered **publicly** by the pair search from the two certificates, so the framing reduction runs the adversary once and outputs the preimage — tight, no extraction, like B0. This glues B0's tight-reduction structure onto a hidden-signer design. With that:

| Row (gate units, 2^18 gates/evaluation, uncapped endpoints) | log₂ Pr/G | Status |
|---|---:|---|
| R1 framing: public pair search → preimage of an honest key, 64×2^10 targets per epoch | −145.0 | tight, named assumption (F one-way given the handle) |
| R2 evasion: two openings of one key; extraction charged (t_B = G + q²·2^12); expansion **E = 512** | −209.0 | named assumption (linear trick is the best collision attack) |
| R3 proof soundness, DFMS22-modelled, τ = 7, 2^32 parties, 32 grinding bits | −159.7 | backend obligation; **multi-round (DFM20) loss not included** |
| R4 honest-proof simulation, GHHM21 Thm 3, 2^64 certificates | −159.4 | proven, QROM |
| R5 pair-search false positive (handle coincidence; corrected in v1.52) | −181.2 | information-theoretic, law measured in `ceqs_games_v1.52.py` |
| **Total** | **−145.0 → D2 margin 15.0 bits** | **PASS** |

Certificate at that setting: **30,810 B** (2^32-leaf trees, 32 grinding bits; 31,322 B with 16 grinding bits, margin 13.2). At 2^24 leaves the rigorous τ = 9 gives 37–38 KB (no fit); at 2^40 leaves, 23,462 B with margin 5.7. Expansion below 430 fails R2 (E = 300: +3.0); more than 2^24 domains per epoch fails R1. The registry key is 128 B at E = 512 (public data; the certificate is unchanged because QuickSilver's size does not depend on the number of constraints).

## 4. Size

FAEST v2 size formula (reproduces FAEST-256s 20,696, -256f 26,548, -EM-256s 17,984, -EM-256f 23,476 to the byte), with the v1.44 Theorem C minimums: challenge bits 212 (180 with a 2^16-step chain), T_open = challenge − grinding, 2 leaf-commit blocks, λ = 256, plus (d − 2)·λ·τ for the degree-3 check.

| Trees | Grinding | Chain | τ | Proof | Certificate | Fits | Prover leaf expansions |
|---:|---:|---:|---:|---:|---:|---|---:|
| 2^16 | 0 | — | 14 | 52,896 | 54,480 | no | 2^19 |
| 2^20 | 8 | 2^8 | 10 | 38,968 | 40,552 | no | 2^23 |
| **2^24** | 16 | 2^16 | 7 | 28,330 | **29,914** | **yes** | 2^26 |
| **2^32** | 16 | 2^16 | 6 | 25,040 | **26,624** | **yes** | 2^34 |

Under the stricter 2^18-gates-per-hash convention the 2^24 row rises to 33,588 B (does not fit) and the 2^32 rows to 27,008 / 23,206 B (fit). Compare Mode A (v1.45): its best published key map needed 41,635 B at 2^40 leaves, and its handle was weak.

### 4.1 A running proof at toy parameters (v1.48)

To test the size accounting against an implementation rather than a formula, `modeB_voleith_toy_v1.48.py` implements the proof system structurally as FAEST does — GGM seed trees, all-but-one vector commitments, VOLE from vector commitments with corrections, a VOLE consistency hash, a QuickSilver degree-3 check with zero-knowledge masks, and a 3-challenge Fiat–Shamir transform — for the exact relation R_B (48 key-map constraints of degree 2, 16 handle constraints of degree 3 with r⁷ made multilinear, 1 selector constraint; 96 committed bits per seat), at toy parameters: GF(2^16) for s, r and the handle, τ = 8 repetitions of 2^8 parties, MAC field GF(2^64).

**Result: the full hidden-signer certificate pipeline runs end to end** — registry, two conflicting frames each carrying a real proof, verification of both, and public pair-search extraction of exactly the 22 common seats with every blame re-verified. Tampered proofs (4 byte positions), a proof reused under a changed message, and a witness that does not open its registry key are all rejected. Toy security only (≈2^−64 soundness), 15 s to prove and 13 s to verify in pure Python.

| Quantity | Bytes |
|---|---:|
| Measured proof (τ = 8, ℓ̂ = 4,320, T_open = 64) | **6,696** |
| Breakdown: 7 corrections 3,780 + witness correction 540 + VOLE hash 16 + QuickSilver 24 + h_com 32 + openings 2,304 | 6,696 |
| FAEST v2 formula at the same parameters, 256-bit nodes as in the toy | 6,924 (3.4% above measured) |
| FAEST v2 formula with λ-bit nodes (the form used for the production sizes in §4 and v1.47) | 5,260 |

The formula's structure — τ·ℓ̂ dominant, T_open·node bits, per-repetition commitment, constants — is reproduced by the implementation; the λ-bit-node version is lower only because the toy opens 256-bit SHAKE nodes for a 64-bit MAC field. Two bugs found and fixed while making it run are recorded in the file's history: the statement must exclude `payload_len` (which depends on the proof length), and the VOLE consistency hash must be checked on the raw correlation q = v ⊕ Δu before the witness correction is applied.

## 5. What is still missing

| Gap | Status | What closes it |
|---|---|---|
| Zero-knowledge backend | toy prototype (v1.48, §4.1) | A production VOLE-in-the-head prover for R_B at n = 256, λ = 256, 2^32-leaf trees (C/Rust; 2^35 leaf expansions per certificate). Its measured size replaces §4. |
| Collaborative prover | none | Whoever holds (s, r) can compute a second handle and frame the seat, so the proof must be produced without any party learning honest openings. Doerner–Kondi–Rosenbloom rule out black-box distribution against all-but-one corruption; the honest-majority case (≤ 21 of 64) is open. 2^24-leaf trees are within reach of MPC-friendly PRG expansion; this is the main research risk. |
| Cryptanalysis | attack families A1–A3 only | Dedicated analysis of "expanding random MQ + power handle": structured Gröbner behaviour, extension-field (Weil descent) formulations, chosen-message effects on c₀ ⊕ c₁. The v1.46 review pass targets these. |
| Security theorem | ledger only (v1.47) | The rigorous ledger passes at n = 256 with a 15-bit margin (§3.4). Still needed: written reductions for framing (tight, via the public pair search), evasion (extraction-charged) and privacy (decisional), and the backend's QROM soundness theorem including the multi-round loss for R3. |
| Collaborative prover, structural analysis | negative | VOLE-in-the-head cannot be split: whoever owns the seed tree learns u, and d = w ⊕ u reveals the witness; two trees give two Δ's and no single VOLE. Generating the tree inside honest-majority MPC costs τ·2^b PRG calls: ≈ 2^35 at the 32-KiB setting, ~10^11–10^12 AND gates. Compactness (big trees) and distributed proving (small trees) pull in opposite directions; the practical model is a trusted aggregator, as in Mode S (premise E7). |
| Registry | 102 B per seat-domain | Acceptable as fixed data; a Merkle alternative would reintroduce hashing in the proof. |
